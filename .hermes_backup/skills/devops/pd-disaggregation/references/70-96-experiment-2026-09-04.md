# 70.96 PD Disaggregation Experiment — 2026-09-04

Node 10.10.70.96, 8× RTX PRO 6000 Blackwell 96GB. Image `10.10.91.56/sw2/fathomless-main-verify:gpu-smoke-fix6`. Runtimes: 0.3.11 (pypi wheel) + 0.3.10.post2 (from 106's proven tar). Scripts on NFS: `/userdata/jianliu/work/tgu01-pro-model-deployment/pd_disaggregation/`.

## Bugs found & fixed (in discovery order)

1. `mooncake_master` lost its +x bit in the tar → `chmod +x`.
2. Flow hardcoded `MOONCAKE_DEVICE=mlx5_bond_0` (106's name) — 96's active RDMA port is **`mlx5_1`** (netdev ens35f1np1, bond0 slave, 10.10.68.96/23, MTU 9000). Patched flow + launch defaults on NFS + local masters.
3. Blank line inside the backslash-continued `docker run` block → `docker run requires at least 1 argument`; stack silently down. `bash -n` does not catch it.
4. **`rdma_transport.cpp:545 Memory region not registered by any active device(s)`** → every KV send ret=-1 after ~2.5 ms (209 descriptors, 5MB) → 0/4 transfers → decode EngineDeadError. Root cause: `nvidia_peermem` module absent on host; default `ibv_reg_mr()` GPU-memory registration impossible. Fix: `-e WITH_NVIDIA_PEERMEM=0` (DMA-BUF path) on P/D containers.

## Runtime A/B (documented dead end)

Swapped 0.3.11 → 0.3.10.post2 (106's proven end-to-end version) BEFORE the peermem fix: identical failure. ⇒ runtime version is not the variable behind the MR signature. After `WITH_NVIDIA_PEERMEM=0`, 0.3.11 ran the full passing matrix. Note: 0.3.10 wheel lacks `.libs/` — its hashed libs must be copied from 0.3.11's `.libs/` with `cp -L` (real files; absolute-path symlinks break in-container).

## Technique: pushing files from WSL to 96

Nested quoting defeats heredocs over ssh. Working pattern: base64 the payload locally (JSON of {filename: b64(content)}), pipe via stdin `printf '%s' '<blob>' | ssh host 'cat > ~/p.b64'`, send a second tiny b64'd python unpacker the same way, run it, md5-verify local vs remote. (Request JSONs for curl: `cat > /tmp/req.json <<EOF` INSIDE the ssh command — single quoting level survives.)
